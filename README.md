# Vitamin-D-Tracker

## 1. Overview

This project measures the live UV index with a low-cost sensor and turns it into **personal vitamin D advice**. Many people do not know how long they should stay in the sun to make enough vitamin D, or when the sun becomes a burn risk. The answer depends on the person (skin type, age, clothing, supplements, body weight) and on the UV level right now.

The system has three parts:

1. **Device (ESP32 + sensor + OLED):** reads UV every few seconds, shows it on a small screen, and sends it over WiFi to the server.
2. **Server (Flask + SQLite):** stores users, profiles and readings, runs the sun-exposure calculations, runs the trained ML model, and serves the dashboard.
3. **Machine-learning model (trained on NHANES):** predicts a person's blood vitamin D level (25-hydroxy vitamin D, in nmol/L) from their profile. The gap to a healthy target decides the daily vitamin D goal.

The dashboard then tells each user: how much UV there is now, how much vitamin D they have made today, how many more minutes they need in the sun, and how many minutes are left before the burn limit.

### How the prediction works

1. The profile form validates and encodes age, sex, BMI, supplementation, and the
   optional sun-habit inputs in the same format used by the saved models.
2. A Gradient Boosting regression model produces the original serum
   25-hydroxyvitamin D estimate in nmol/L. The basic model uses age, sex, BMI, and
   supplementation; the sun-habits model also uses outdoor exposure and skin reaction.
3. The original prediction is preserved. The separate `health_adjustments.json`
   layer then applies configured experimental health deductions and milk bonuses
   once, including the combined deduction cap and kidney/diabetes overlap rule.
4. The final estimate is clipped to the configured valid target range. The dashboard
   displays both predictions, every applied contribution, the total adjustment,
   model error context, and planning guidance.

The model estimate is not updated by a live blood measurement unless the user adds a
laboratory result on the blood-test page. Sun-exposure and IU values are separate
planning calculations and should not be interpreted as a measured change in serum
25(OH)D.

### Model verification and accuracy

The saved models predict serum 25-hydroxyvitamin D (`LBXVIDMS`) in nmol/L from
NHANES 2013-2014 patterns. They are screening models, not blood tests, diagnoses, or
clinical decision tools.

The current saved-artifact verification results are:

| Model | Inputs | Rows | MAE | RMSE | R² |
|---|---|---:|---:|---:|---:|
| Basic Gradient Boosting | Age, sex, BMI, supplementation | 5,596 | 18.04 nmol/L | 23.81 nmol/L | 0.255 |
| Sun-habits Gradient Boosting | Basic inputs plus outdoor exposure and skin reaction | 3,541 | 17.39 nmol/L | 22.74 nmol/L | 0.192 |

MAE is the typical absolute error in the evaluation, not a guaranteed uncertainty interval.
For example, the basic model's MAE of 18.04 nmol/L means that absolute errors averaged
about that size in this evaluation; it does not mean an individual result will be within
18.04 nmol/L. An individual prediction can be considerably higher or lower than the
displayed number. R² describes explained variation in this dataset and should not be
interpreted as clinical accuracy.

`check_model.py` currently passes **22 of 22 checks**. The checks verify model type and
feature lists, valid metrics, predictions against NHANES rows, realistic output ranges,
calibration direction, feature-direction examples, extreme inputs, and the Flask prediction
path. On the verification rows, the sun model's MAE was **17.0 nmol/L**, compared with
**19.5 nmol/L** for an always-predict-the-average baseline, and predicted-value groups rose
in the same direction as observed average vitamin D.

These are software and dataset checks, not proof of clinical validation. The survey is
observational, the model was not trained on Indian participants, and a 25(OH)D blood test
is required to know an individual's actual level.

The deficiency table below is a separate screening evaluation, not a replacement for the
regression prediction. It uses nested out-of-fold validation: thresholds are selected from
inner training folds and scored only on untouched outer folds. The latest report contains
5 outer folds for each model scope and was generated by `evaluate_deficiency.py`.

#### Deficiency classification investigation

The original `LBXVIDMS < 30 nmol/L` metric thresholded the regression prediction at
30 nmol/L. In the current verification data, this produced no predicted deficient cases:
precision, recall and F1 were 0%, with specificity 100%. The ROC AUC values near 0.74-0.75
show ranking signal, but do not mean the fixed threshold is useful for finding cases.

`evaluate_deficiency.py` compares the regression approach with class-weighted Random Forest
and class-weighted HistGradientBoosting classifiers. It uses five outer stratified folds;
each threshold is selected only from inner training-fold predictions, and outer validation
labels are not used for threshold selection. The latest run also reports accuracy,
bootstrap 95% intervals for the primary operating point, and multiple outer-fold
operating points to show the precision-recall trade-off. Latest results:

| Scope / method | Accuracy | Actual | Predicted | TP | FP | FN | Precision | Recall | Specificity | F1 | PR-AUC | ROC-AUC |

| Basic regression, threshold 54.5 nmol/L | 77.6% | 452 | 1,204 | 202 | 1,002 | 250 | 16.8% | 44.7% | 80.5% | 24.4% | 0.173 | 0.718 |
| Basic Random Forest, probability 0.444 | 73.9% | 452 | 1,446 | 219 | 1,227 | 233 | 15.1% | 48.5% | 76.1% | 23.1% | 0.161 | 0.702 |

Bootstrap 95% intervals for the selected regression operating points were:

| Scope | Accuracy | Precision | Recall | Specificity | F1 |
|---|---:|---:|---:|---:|---:|
| Basic, threshold 54.5 | 76.5-78.6% | 14.8-18.8% | 40.2-49.1% | 79.4-81.6% | 21.8-27.0% |

For example, the basic regression threshold trade-off was precision/recall of
0.0%/0.0% at 30 nmol/L, 21.0%/14.6% at 50 nmol/L, 16.8%/44.7% at 54.5 nmol/L,
and 11.0%/93.6% at 70 nmol/L. These are different screening operating points on
the same outer predictions, not additional model claims.

The selected regression thresholds had the highest F1 and PR-AUC among the tested
approaches in this run, so no dedicated classifier or new model artifact was promoted
into the prediction path. The basic threshold was selected at 54.5 nmol/L and the
sun-habits threshold at 51.1 nmol/L by maximizing inner-training-fold F1 with recall
as a tie-break. These are experimental screening cutoffs, not clinical diagnostic
thresholds. They improve recall at the cost of many false positives.

The objective used here is balanced screening performance, represented by F1 with
recall as a tie-break, rather than accuracy alone. No tested method improved both
precision and recall simultaneously, so the existing regression artifacts remain the
production baseline.

### Level progression and adherence

The regression model is a screening estimate; it is not a blood-test result and it does not
automatically become more accurate as time passes. The tracker now keeps a separate,
user-confirmed daily adherence record. A user can record whether today's prescribed dose was
taken. Completed sun sessions are added from the UV sensor automatically.

The dashboard trajectory starts from the latest saved 25(OH)D lab value when one exists,
otherwise it starts from the model prediction. For each day it combines logged supplement
adherence with completed sun-session IU, then uses a bounded first-order response model:
approximately a 21-day 25(OH)D half-life, about 1 nmol/L per 100 IU/day as a conservative
planning response, and a personal response shift capped so the estimate cannot increase
without limit. This reflects evidence that 25(OH)D changes over weeks and commonly approaches
a new plateau over roughly 8-12 weeks, rather than jumping immediately.

A missed or unlogged dose can therefore trend down, while a taken dose plus sun exposure can
trend up; neither is guaranteed because the curve is an estimate. An unlogged day with no
recorded sun or supplement input has a gradual natural decline, while any recorded sun session
or taken dose contributes a positive response. The graph shows historical tracker data plus
a dashed projection for the selected range (7, 30, 60, 90, 180, or 365 days). These values
are planning estimates only; a repeat 25(OH)D blood test and clinician advice are needed before
changing treatment.

The signed-in navbar includes a separate **Progress** page. It records a starting estimate
when the user first completes their profile after registration, displays that starting value
and date beside the current estimate, and compares the change over time. Existing accounts are
backfilled with a starting snapshot the first time they open the Progress page.

### Health adjustment layer

The Gradient Boosting models used by the app intentionally contain only the core predictors
(age, sex, BMI, supplementation, and, for the sun model, outdoor exposure and skin reaction).
Health and lifestyle answers are applied once, in the separate configurable
`health_adjustments.json` layer. Its constants are residual contrasts calculated from the
NHANES 2013-2014 training split after the core model prediction; this avoids subtracting a
constant for an effect that the model already learned. Disease and smoking YES answers use
positive deduction magnitudes, while NO answers contribute zero. Alcohol
categories are estimated separately and milk is intentionally zero because its category
contrasts are not consistently directional.

These are observational, project-specific heuristics, not clinically validated effects.
`train_health_adjustments.py` records each sample size, missing count, raw contrast,
reliability flag, and the valid target bounds (9.37 to 318.0 nmol/L). Re-run it only when
the NHANES inputs or model training procedure changes.

The raw constants are preserved in `health_adjustments.json`. They are re-estimated from
five-fold out-of-fold residuals rather than in-sample residuals. For a negative observed
contrast, the applied estimate is shrunk by one standard error:
`-max(0, abs(raw contrast) - standard error)`. An observed non-negative association is
not converted into a negative disease penalty, so kidney, liver, thyroid, diabetes and
weak-bones currently have zero applied binary penalty; their positive raw contrasts remain
documented for review. Smoking has a small applied value after uncertainty shrinkage.

The runtime uses two configurable experimental limits: `MAX_SINGLE_HEALTH_DEDUCTION_NMOL`
(currently **2.0 nmol/L**) and `MAX_HEALTH_DEDUCTION_NMOL` (currently **4.0 nmol/L**).
The first limits each binary contribution and the second limits the combined binary
pool. These are project heuristics, not medically validated thresholds. Kidney disease
and diabetes are overlapping conditions in this heuristic, so when both are selected the
larger configured deduction is retained and the smaller one is shown as
overlap-suppressed. The current academic demonstration magnitudes are: kidney **1.0**,
liver **0.5**, thyroid **1.5**, diabetes **1.0**, weak bones **0.5**, and smoking
**1.0 nmol/L**. These are explicit experimental overrides; the raw OOF estimates and
uncertainty are retained separately and are not evidence that these deductions are
causal or clinically valid. Alcohol remains a separate category adjustment. Milk uses
experimental demo bonuses of **+1.0 nmol/L** for rarely, **+1.5 nmol/L** for sometimes,
and **+2.5 nmol/L** for every day; never, missing, and unrecognized values receive zero.
These are not scientifically validated individual effects. The final calculation is
`clip(original prediction - total binary deduction + separate lifestyle adjustment)`.
